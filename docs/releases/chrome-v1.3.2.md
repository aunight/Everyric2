# Everyric Chrome 확장 1.3.2

실사용에서 드러난 결함 묶음을 고칩니다. **가장 심각한 것은 자동 생성 자막이 정상 가사를 대체하고 그대로 영구 싱크로 저장되던 문제**입니다.

## 무엇이 잘못됐었나

한 영상에서 이런 연쇄가 일어났습니다.

1. **싱크 초기화**를 누름 → 서버의 정상 싱크가 삭제됨
2. 재조회가 서버·위키·LRCLIB 전부 미스 → **자막 폴백**이 발동
3. 그 영상에는 자동 생성(ASR) 자막만 있었고, 노래를 ASR로 받아 적은 텍스트가 가사 자리에 들어왔음
   (`縋って いつも縋って` → `すがっていつもすがって おち読も`)
4. 그 상태에서 생성을 누르니 **ASR 전사가 서버에 영구 싱크로 저장됨** — 모든 사용자에게 그 텍스트가 원문이 됨
5. 자막 경로는 번역·발음을 아무도 만들지 않아 **발음 0줄 / 번역 0줄**
6. 그런데도 알림은 "가사 싱크가 준비됐어요"

## 고친 것

- **초기화가 원문 가사를 잃지 않습니다.** 초기화는 타이밍을 버리는 것이고 가사를 버리는 게 아닙니다. 지운 가사를 화면에 남겨, 자막 폴백으로 갈아타지 않고 **그 가사로 바로 다시 생성**할 수 있습니다.
- **자동 생성 자막으로는 싱크를 만들지 않습니다.** 화면 표시는 그대로 두되(있으면 도움이 됩니다) 생성 버튼 대신 사유를 보여 줍니다. 노래에서 ASR 전사 정확도는 원문으로 쓸 수 없는 수준이고, 한 번 저장되면 모든 사용자의 원문이 됩니다.
- **자막으로 만든 싱크에도 번역·발음이 붙습니다.** 서버가 가사를 조달하는 경로이므로 번역·독음도 서버가 만들어 붙입니다. 다운로드·보컬 분리와 겹쳐 돌기 때문에 체감 시간은 늘지 않습니다.
- **붙여넣은 가사가 버려지지 않습니다.** 자막이 떠 있는 상태에서 정확한 원문을 붙여넣으면 자막이 대신 쓰였습니다. 이제 넘어온 텍스트로 판단합니다.
- **완료 알림이 결과를 봅니다.** 잡이 끝났다는 사실만으로 "준비됐어요"라고 하지 않고, 발음·번역이 붙지 않았으면 무엇이 빠졌는지 말합니다.

## PiP 창

- **영상을 넘길 때 가라오케 모드가 풀리던 문제** — 검색을 시작할 때 띄운 패널이 화면을 점유한 채 남아, 싱크가 도착해도 음정 레인이 닫혀 있었습니다.
- **영상 표시가 이전 곡에 멈춰 있던 문제** — 미러는 `captureStream`이라 영상이 바뀌면 트랙이 끝납니다. 싱크가 없는 곡·조회 실패에서도 재부착하고, 광고↔본편처럼 엘리먼트는 그대로인데 소스만 바뀌는 전환도 따라갑니다.
- **제목이 갱신되지 않던 문제** — PiP는 창을 열 때 한 번만 제목을 받았습니다. 창을 열던 순간 광고가 재생 중이었다면 광고 제목이 계속 남았습니다.

## 설치

> Chrome은 웹스토어 외부 확장의 일반 설치를 막기 때문에 개발자 모드로 로드합니다.

1. 아래 **Assets**에서 `Everyric-Chrome-1.3.2.zip`을 받아 압축을 풉니다.
2. `chrome://extensions` 접속 → 우상단 **개발자 모드** 켜기.
3. **압축해제된 확장 프로그램 로드** → 압축 푼 폴더 선택.
   - 이전 버전을 이미 로드해 두셨다면, 같은 폴더 내용을 새 압축 해제본으로 바꾼 뒤 확장 카드의 **새로고침** 버튼만 누르면 됩니다.
4. 서버 기능을 쓰려면 설정에서 **API 키**를 입력합니다. 서버 주소는 기본값이 채워져 있습니다.

## 이미 만들어 둔 싱크

이번 수정은 **새로 생성·재생성할 때** 적용됩니다. 자동 생성 자막으로 만들어진 싱크가 이미 있다면, 정확한 가사를 붙여넣어 다시 생성해야 원문이 바로잡힙니다.
