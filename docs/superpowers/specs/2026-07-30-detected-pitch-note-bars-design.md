# 實際麥克風音高條設計

## Problem 1-Pager

### 背景（Background）

Everyric 的「命中音符（日K）」模式目前會把麥克風樣本映射到同時間的目標音符，
再把目標音符的部分區段塗成金、黃或紅色。這能表示判定結果，卻不能顯示使用者
真正唱出的音高；唱高或唱低時，顏色仍出現在原曲音符上，看起來像只替原曲音符變色。

### 問題（Problem）

`buildNoteHitSegments()` 會捨棄麥克風樣本的實際 MIDI 音高，改用目標音符的 MIDI，
並排除不屬於目標音符時間窗的樣本。繪圖層又依 `noteIndex` 把結果畫在目標音符上，
因此「命中音符」模式無法呈現真實歌唱位置及高低偏差。

### 目標（Goal）

- 「命中音符（日K）」顯示麥克風即時偵測到的實際音高條。
- 音高條使用樣本的實際 MIDI 決定垂直位置，不貼回目標音符。
- 命中為金色、接近為橘色、失誤為紅色。
- 即使唱錯或沒有對應目標音符，可靠的麥克風音高仍保持可見。
- 原曲目標音符維持灰色，作為歌唱目標與實際音高的對照。
- 保留「線條軌跡」模式、既有分數公式及設定相容性。

### 非目標（Non-goals）

- 不更換麥克風音高偵測器或旋律擷取模型。
- 不導入 RMVPE、MuScriptor、GAME、Demucs 或 Dereverb。
- 不修改命中門檻、八度折疊判定或總分公式。
- 不修改歌詞、假名、翻譯、分數保存或歌曲音符資料。
- 不模仿 DAM／日K 的其他特效、技巧判定或計分介面。

### 約束（Constraints）

- 沿用現有 Canvas、`MicPitch`、`ScoreTracker` 與 `micDisplayMode`。
- 持久化值仍為 `notes`，避免破壞既有 Chrome 設定。
- 必須保留換氣與偵測中斷，不得用長條填補無可靠音高的空白。
- 必須限制繪圖歷史與可見時間窗，避免長時間播放造成效能退化。
- 新的分段邏輯必須是可由 Node 直接測試的純函式。

## 方案比較

### A. 實際音高短條＋判定色（採用）

把連續麥克風樣本依實際半音分組成短橫條。橫條高度由麥克風 MIDI 決定，顏色只負責
表示與目標音符的接近程度。它能直接看出唱高、唱低與持續時間，也保留日K音符條的
閱讀方式。

### B. 只保留連續折線

現有「線條軌跡」已能顯示真實音高，重用它的實作最少；但兩個模式會失去差異，
也不符合使用者指定的音符條呈現。

### C. 目標音符變色＋額外偏差標記

可以保留目前覆蓋效果，再以箭頭或小點表示高低偏差；資訊完整但畫面更亂，
且使用者仍難以一眼看出實際唱到哪個音。

## 資料與分段

新增純函式把已評分的 `MicTracePoint` 轉成實際音高條：

1. 依歌曲時間排序樣本。
2. 每個樣本保留原始麥克風 MIDI，不再查找或複製目標音符 MIDI。
3. 顯示音高以最近半音量化，讓短條穩定落在音高格線上；評分仍使用未量化的原始 MIDI。
4. 相鄰樣本時間差不超過 160ms、量化音高相同且判定相同時合併。
5. 最後一個樣本補最多 80ms 的可見尾段。
6. 時間中斷、換氣、音高改變或判定改變時另起一條。
7. `judgement === null` 的可靠樣本也可以顯示，使用中性色；採點時間窗內的
   `hit`、`near`、`miss` 分別使用金、橘、紅色。

不再以 `noteIndex` 分組，也不把開始／結束時間裁到目標音符範圍。

## 繪圖順序

1. 繪製格線、側欄與灰色目標音符。
2. 繪製目標音符上的歌詞與發音。
3. 在所有目標音符之上繪製實際麥克風音高條：
   - X 軸取樣本的歌曲時間。
   - Y 軸取量化後的麥克風 MIDI。
   - 高度接近目標音符條，並加深色細外框以維持對比。
   - 金色代表命中、橘色代表接近、紅色代表失誤、中性色代表尚無目標判定。
4. 繪製分數 HUD 與其他既有上層介面。

目標音符不再因麥克風判定而改色。播放進度也不在 `notes` 模式替目標音符填色，
讓灰色目標與彩色實際歌聲保持明確區分。

## 狀態與邊界

- 麥克風未啟動：只顯示灰色目標音符與既有「麥克風關閉」狀態。
- 麥克風已啟動但無聲：不產生音高條，也不填補空白。
- 唱錯但有可靠音高：紅色音高條畫在真正偵測到的位置。
- 沒有同時間目標音符：中性色音高條仍可顯示，分數行為維持現況。
- 音高超出可見音域：沿用畫面既有八度視窗校正與裁切規則，不改變評分用 MIDI。
- 切換 `trace`／`notes`：只切換繪圖策略，不重設分數或麥克風歷史。

## 測試與驗收

先建立失敗測試，至少涵蓋：

1. 實際 MIDI 61 的樣本對上目標 MIDI 60 時，輸出音高條仍為 61。
2. 目標音符時間窗外的可靠樣本仍能產生實際音高條。
3. 相同量化音高、判定與連續時間的樣本會合併。
4. 換氣、時間中斷、音高或判定改變會切斷音高條。
5. `notes` 模式直接依音高條 MIDI 計算 Y 軸，不再建立 `hitsByNote`。
6. 目標音符保持灰色，實際音高條使用金、橘、紅與中性色。
7. `trace` 模式、設定遷移、歌詞與發音繪製測試維持通過。

完成後執行 Chrome 擴充功能全量測試、型別檢查、採點自檢腳本、production build
與 `git diff --check`。實際驗收時，故意唱高或唱低，彩色音高條必須出現在相對應
的高／低格線，而不是只替灰色目標音符變色。
