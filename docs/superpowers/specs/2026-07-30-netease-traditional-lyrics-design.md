# 網易雲中文歌詞智慧繁體化設計

## Problem 1-Pager

### 背景（Background）

網易雲音樂的 `lrc` 原文與 `tlyric` 翻譯經常使用簡體中文。Everyric 已內建
OpenCC `cn → tw` 轉換器，但目前只套用在 `tlyric` 翻譯行及搜尋比對正規化，
`lrc` 原文解析後直接送入一般歌詞、PiP 與採點畫面。因此中文歌曲仍顯示
「这、张、卫、点、烟」等簡體字。

網易雲也提供日文歌曲；若不判斷語言就把所有原文送入 OpenCC，可能把日本漢字改成
臺灣繁體字形，破壞原始日文歌詞。

### 問題（Problem）

`neteaseToLyricsData()` 只在建立翻譯時間對照表時呼叫 `s2t(tr.text)`，
但沒有轉換 `parseLRC(lyric.lrc)` 產生的：

- `LyricLine.text`
- 選配的 `LyricLine.words[].word`
- 最終 `plainText`

同一份簡體原文會被所有歌詞表面共用，造成一般歌詞、PiP 與採點畫面一起顯示簡體。

### 目標（Goal）

- 網易雲原文整體判定為中文時，統一轉成繁體中文。
- 中文原文的行文字與逐字時間文字都必須轉換。
- 網易雲 `tlyric` 中文翻譯繼續轉成繁體。
- 日文、韓文及英文原文保持來源文字，不套 OpenCC。
- 一般歌詞、PiP、採點及 `plainText` 共用同一份轉換後資料。
- 轉換集中在網易雲資料轉換層，不在各個 UI 重複處理。

### 非目標（Non-goals）

- 不把日文漢字改成臺灣繁體字。
- 不翻譯歌詞語意，只做簡繁字形轉換。
- 不修改 LRCLIB、Everyric 伺服器或 YouTube 字幕來源。
- 不調整網易雲搜尋、候選排序或翻譯顯示語言規則。
- 不處理藝人名稱、採點、RMVPE、Demucs 或 Dereverb。

### 約束（Constraints）

- 沿用現有 `opencc-js`，不加入新的字典或網路服務。
- 語言判斷沿用共用的 `detectLyricLanguage()`，避免 UI 與資料層規則分歧。
- 必須先解析整首歌再判定語言；不能逐行判定，否則日文歌的漢字行可能被誤當中文。
- 轉換後的行文字、逐字文字及 `plainText` 必須一致。
- 網易雲人工作翻譯、時間對齊及語言層欄位必須保持現有行為。

## 方案比較

### A. 資料層整首判定後轉換（採用）

解析完整 `lrc`，用整首文字判定語言。只有結果為 `zh` 時才轉換原文行及逐字資料；
`tlyric` 仍一律視為中文翻譯並轉繁體。所有畫面收到的資料天然一致。

### B. 所有網易雲原文強制轉換

程式最少，但會更動日文原文中的日本漢字，不可接受。

### C. 各 UI 繪製前轉換

會在一般歌詞、PiP 與採點重複邏輯，也可能造成匯出、搜尋或生成流程仍使用簡體。

## 元件與資料流

新增 `src/lib/netease-lyrics.ts`，集中負責：

1. 解析網易雲 `lrc`。
2. 以 `detectLyricLanguage(lines.map(line => line.text))` 判定整首原文。
3. 若為 `zh`：
   - 轉換每個 `line.text`。
   - 轉換每個 `line.words[].word`。
4. 解析 `tlyric`，把每一行翻譯轉成繁體後依現有 10ms 時間鍵對齊。
5. 從完成轉換的 `lines` 重建 `plainText`。
6. 保留 `humanTranslated`、`translationLang`、`availableLangs` 與
   `translationsByLang` 的既有判定。

`background.ts` 改為匯入此純轉換函式，不再自行持有 OpenCC 轉換器。
`netease.ts` 的 OpenCC 仍只服務簡繁不敏感的搜尋比對，但註解需更新，不能再宣稱
顯示層不做繁體轉換。

## 轉換規則

### 中文原文

整首判定為 `zh` 時：

- `静止了这世界像张照片` → `靜止了這世界像張照片`
- `卫星拍下的姿态` → `衛星拍下的姿態`
- `点不着的香烟` → `點不著的香煙`

若 LRC 含逐字時間標記，`line.text` 與 `line.words[].word` 使用同一轉換器，
避免大字歌詞與採點音符文字不一致。

### 日文原文

整首含有假名而判定為 `ja` 時，原文完全不變，例如：

- `叶えたい未来がある` 保持 `叶えたい未来がある`

日文歌曲的中文 `tlyric` 仍轉成繁體並作為翻譯層顯示。

### 其他語言

韓文、英文或無法判斷的原文不轉換；若有 `tlyric`，只轉換該中文翻譯層。

## 錯誤與邊界

- `lrc` 為空或解析不到有效行：維持回傳 `null`。
- 原文已是繁體：OpenCC 轉換保持等價結果。
- 中英混合但包含中文漢字、沒有假名：依共用語言判斷視為中文並轉換漢字。
- 日文歌包含純漢字單行：整首只要有其他假名，仍判定為日文，所有原文行都不轉。
- `tlyric` 缺少對應時間：維持既有行為，不建立錯位翻譯。
- 轉換器或 UI 不新增例外分支；使用現有同步純函式。

## 測試與驗收

先建立失敗測試，涵蓋：

1. 中文網易雲 `lrc` 的 `line.text` 與 `plainText` 轉成繁體。
2. 含逐字時間的中文 `words[].word` 同步轉成繁體。
3. 日文原文含假名時完全不轉換日本漢字。
4. 日文歌曲的簡體 `tlyric` 仍轉成繁體。
5. 中文翻譯時間對齊、`translationsByLang.zh` 與目標語言顯示行為維持。
6. `background.ts` 只呼叫共用網易雲轉換函式，不保留第二份轉換邏輯。

完成後執行 Chrome 擴充功能全量測試、型別檢查、production build 與
`git diff --check`。驗收時，以截圖中的網易雲中文歌測試，畫面必須顯示
「靜止了這世界像張照片」、「點不著的香煙」，日文歌曲則維持原始日本漢字。
