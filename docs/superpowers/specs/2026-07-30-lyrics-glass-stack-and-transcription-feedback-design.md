# 歌詞毛玻璃頂層與 AI 轉錄即時回饋設計

## Problem 1-Pager

### 背景（Background）

Everyric2 Chrome 擴充套件目前以垂直 flex 排列標題列、語言列、AI 轉錄提示列與歌詞本文。
先前僅透過 `.ey-under-chips` 的固定負邊距，讓歌詞局部移到語言列底下。標題列與 AI
提示列仍佔用正常版面，動態出現的提示列高度也沒有納入疊層計算。

按下「執行 AI 轉錄」後，內容層雖會把工作放入 `preparingGenerate` 並更新獨立的小型進度
chip，但原本的黃色提示列沒有立刻切換狀態。使用者看到的主要操作區因此像是沒有反應。

### 問題（Problem）

- 歌詞到達語言列或黃色提示列時被硬切斷，甚至與提示文字重疊。
- 上方區塊沒有各自形成清楚、圓角的毛玻璃層，視覺上像一整塊不透明底板。
- 固定 `44px` 的負邊距不能處理標題、提示、伺服器狀態等動態高度。
- AI 轉錄的主要按鈕沒有在點擊當下提供同位置的狀態變化，造成「按了沒反應」。

### 目標（Goal）

- 歌詞可以完整滑到標題列、語言列與 AI／狀態列底下，不在區塊邊界被裁切。
- 標題列、語言列、黃色 AI 提示列各自使用半透明、圓角範圍內的毛玻璃背景。
- 黃色提示保留黃色調；轉錄開始後，同一視覺位置立刻切成紫色毛玻璃進度列。
- 頂層高度依實際可見內容動態更新，不以固定像素猜測。
- 保留設定頁、拖曳、縮合、錯誤提示、取消轉錄與生成佇列等既有行為。

### 非目標（Non-goals）

- 本次不重新設計採點／麥克風音高視覺化。
- 不修改後端轉錄演算法、工作佇列或進度數值。
- 不將所有通知都改成頂層提示列；只處理與目前歌曲 AI 轉錄直接相關的主狀態。
- 不重做整個 Overlay 或 PiP 架構。

### 約束（Constraints）

- 上方任一列顯示、隱藏、換行或改變高度時，歌詞初始位置仍須正確。
- 毛玻璃需同時提供 `backdrop-filter` 與 `-webkit-backdrop-filter`。
- 透明背景必須有足夠色調，避免底下歌詞穿透後影響文字可讀性。
- 設定頁層級必須高於歌詞頂層，返回按鈕不能再次被語言列遮住。
- 不覆寫工作區中現有、與本修改無關的未提交變更。

## 方案比較

### A. 固定負邊距

延伸現有 `.ey-under-chips`，為標題和提示列加入更多固定偏移。改動最小，但任一列換行、
伺服器錯誤列出現或文案高度變化後就會失準，因此不採用。

### B. 將所有上方列放入歌詞捲動器並設為 sticky

語意直觀，但需要大幅改變既有 DOM、捲動事件、auto-scroll 與設定頁定位，回歸風險較高。

### C. 動態浮動頂層（採用）

建立獨立的頂層容器，讓標題、語言與狀態列浮在歌詞捲動區上方；以 `ResizeObserver` 測量
實際高度，將高度寫入 CSS 變數，作為歌詞初始安全間距。歌詞捲動後仍會進入頂層下方。

## 詳細設計

### DOM 與版面

- 新增 `.ey-top-stack`，包含標題列、語言列、伺服器狀態、AI 提示／進度與必要的頂部通知。
- `.ey-top-stack` 絕對定位於面板上緣，層級低於設定頁、高於歌詞本文。
- `.ey-body` 仍是唯一歌詞捲動器，填滿可用高度；以
  `padding-top: var(--ey-top-stack-height)` 保證初次載入時第一行完整顯示。
- 捲動內容可以進入這段 padding 以上的區域，因此歌詞會自然滑到所有頂層列下方。
- 移除 `.ey-under-chips` 及固定 `44px`／`52px` 偏移。
- footer 保持在底部，不納入頂層。

### 動態高度

- 使用獨立 `ResizeObserver` 監看 `.ey-top-stack`。
- 每次高度變化後，把實際像素值寫入 panel 的 `--ey-top-stack-height`。
- 顯示／隱藏語言列、AI 提示、進度、伺服器錯誤或通知時，不需要各自維護偏移數字。
- Overlay 銷毀時一併中止 observer。

### 個別毛玻璃

- 標題列：深色半透明背景、較強模糊，保留面板上緣圓角。
- 語言列：較輕的深色半透明背景與獨立圓角，不與標題列合成一整塊底板。
- AI 提示列：保留黃色色調，改為半透明黃色毛玻璃與圓角。
- 進度列：使用紫色半透明毛玻璃，與黃色提示佔用同一視覺位置。
- 各列保留細邊框或間距，讓使用者能辨識它們是分開的互動區塊。

### AI 轉錄狀態

1. 使用者按下黃色列的「執行 AI 轉錄」。
2. 既有 `handleGenerate` 通過基本輸入檢查、加入 `preparingGenerate` 後，立即呼叫
   `updateGenChip()`。
3. Overlay 收到非空 generation text 時，隱藏黃色提示列，並在相同 slot 顯示紫色進度列；
   第一個狀態為「準備產生時間軸…」。
4. 工作建立後，紫色列在同一位置更新為佇列、階段與總進度，保留取消及展開佇列能力。
5. 若請求在建立工作前失敗，紫色列消失、黃色操作列恢復，既有錯誤提示保留可見。
6. 工作完成後重新載入 Everyric 歌詞；黃色提示不再需要。工作失敗時恢復原歌詞和可重試的
   黃色操作列，並顯示錯誤原因。

不把狀態改成只存在數百毫秒的按鈕 loading 樣式；整列切色能提供更明顯且連續的回饋。

### 設定頁與折疊

- `.ey-settings` 保持比 `.ey-top-stack` 更高的 z-index。
- 設定頁仍從標題列下方開始，返回按鈕保持可見、可點擊。
- collapsed 狀態只保留標題列，其他頂層列與歌詞依既有規則隱藏。

## 錯誤與邊界

- 無影片 ID、空白歌詞、超過 500 行或自動字幕禁止生成時，不切成持續的紫色狀態；顯示
  既有驗證訊息。
- 重複點擊已在準備／轉錄中的歌曲，不建立第二個工作。
- 伺服器拒絕或網路錯誤時，`finally` 必須清除 preparing 狀態，不能讓紫色列永久卡住。
- 透明毛玻璃在不支援 filter 的瀏覽器仍靠半透明底色維持可讀性。

## 測試與驗收

- DOM 測試：頂層包含標題、語言、伺服器狀態、AI 提示與進度 slot；歌詞 body 不再使用
  `.ey-under-chips`。
- CSS 測試：頂層覆蓋歌詞；body 使用動態頂層高度；標題、語言、黃色提示、紫色進度各有
  半透明背景、圓角及雙前綴 blur。
- 狀態測試：generation text 出現時黃色提示隱藏、紫色進度顯示；清除後可恢復提示。
- 互動測試：按下 AI 轉錄後，在伺服器回應前就能看到紫色「準備中」。
- 回歸測試：設定頁層級、返回按鈕、取消工作、佇列展開、collapsed、TypeScript 型別檢查
  與 Vite 正式建置全部通過。
- 實機驗收：重新載入 Chrome 擴充套件後，在有外部同步歌詞的 YouTube 影片確認：
  1. 第一行不被裁切。
  2. 捲動時歌詞依序滑到黃色列、語言列與標題列底下。
  3. 每列都有獨立毛玻璃，而不是一整片黑底。
  4. 點擊轉錄後黃色列立即變成紫色狀態列。
