# 採點顯示雙模式與音符歌詞修復設計

## Problem 1-Pager

### 背景（Background）

Everyric 的採點音高軌目前可用粗線或點狀顯示麥克風偵測結果。使用者提供
DAM 精密採點畫面作為參考：未唱的目標音符保持暗色，唱過的區段會依命中程度
直接變色；新版 DAM 也能另外顯示即時歌唱軌跡。

目前採點音符上的原文歌詞和發音共用 `pron` 欄位，並受
`pitchPronPosition === "note"` 控制。歌曲沒有發音分段，或使用者把發音位置改到
畫面底部時，音符原文也會一起消失。

### 問題（Problem）

1. 「線／點」不是使用者需要的兩種採點呈現。
2. 缺少接近日 K 的「直接在目標音符顯示命中結果」模式。
3. 音符原文與發音耦合，導致歌詞被發音設定隱藏。
4. 設定頁沒有明確的採點顯示方式選項。

### 目標（Goal）

- 採點顯示提供「線條軌跡」與「命中音符」兩種模式。
- 「命中音符」模式把已唱過的目標音符區段依準確度顯示為金、黃或紅色。
- 音符原文獨立於發音資料及發音位置，任何模式都保持可見。
- 設定頁與 PiP 快速按鈕操作同一份持久化設定。
- 舊版 `dots` 設定能無錯誤地遷移。

### 非目標（Non-goals）

- 不修改分數公式與命中門檻。
- 不修改麥克風音高偵測器。
- 不修改旋律擷取、歌詞同步或音符時間。
- 不加入唱法技巧、排行榜或 DAM 的其他視覺特效。

### 約束（Constraints）

- 保留現有髒工作樹中的其他使用者修改。
- 使用現有 `MicSample`、`ScoreTracker` 與旋律音符資料。
- 中文音符必須顯示漢字原文；其他語言也優先顯示歌曲原文。
- 模式切換不能重置進行中的分數。
- Chrome 儲存空間中的舊設定必須向前相容。

## 使用者體驗

### 設定頁

新增「採點顯示方式」下拉選單：

- `線條軌跡`：在音高格線上繪製麥克風實際歌唱軌跡。
- `命中音符`：不繪製獨立軌跡，直接替唱過的目標音符區段上色。

PiP 底部保留快速切換按鈕，文字為：

- `線`：目前是線條軌跡。
- `音`：目前是命中音符。

按鈕標題會說明目前模式及點擊後的切換結果。設定頁與 PiP 按鈕共用
`micDisplayMode`，任一處修改都立即反映並保存。

### 線條軌跡

沿用現有分段粗線：

- 命中：綠色。
- 接近：黃色。
- 失誤：紅色。
- 尚無目標音符：青色。
- 長時間中斷或音高大幅跳動時斷線。

### 命中音符

目標音符底層始終先畫暗色導唱條。麥克風樣本按時間映射到所屬目標音符後，只在
樣本覆蓋的短時間區段畫評分覆蓋層：

- 完準／命中：金色。
- 接近：黃色。
- 失誤：紅色。
- 沒有唱到的區段維持暗色。

覆蓋層沿用樣本的時間粒度，不把整顆音符一次塗滿；這樣能看出同一長音內哪一段準、
哪一段偏離。播放頭與現有分數 HUD 保持不變。

## 音符文字資料

`PitchNote` 拆成兩種文字：

- `lyric`：歌曲原文，與音符按時間重疊或最近距離配對，永遠可以繪製。
- `pron`：選配發音，只受發音語系與 `pitchPronPosition` 控制。

原文不再經過 `resolvedPronSegments`。中文固定取 `word.word` 的漢字；其他語言也從
原始 `line.words` 取得。`pron` 保持現有羅馬拼音、韓文或假名選擇邏輯。

繪製順序為：

1. 格線與音高側欄。
2. 暗色目標音符。
3. 命中音符覆蓋層（僅命中音符模式）。
4. 音符原文。
5. 選配發音。
6. 線條軌跡（僅線條軌跡模式）。
7. HUD、下方歌詞與翻譯。

音符太短時，原文仍從音符起點畫出並由 Canvas 裁切；不因寬度門檻完全省略。

## 設定與遷移

`micDisplayMode` 改為：

```ts
type MicDisplayMode = "trace" | "notes";
```

預設為 `notes`，讓新安裝預設接近日 K 的導唱音符效果。

讀取舊設定時：

- `line` 轉為 `trace`。
- `dots` 轉為 `trace`。
- 未知值轉為 `notes`。

遷移只在讀取與儲存正規化層處理，PiP 不接受舊值。

## 元件與資料流

1. `settings.ts` 讀取並正規化模式。
2. `overlay.ts` 提供下拉選單並呼叫既有 `onSettingsChange`。
3. `content.ts` 把模式傳入 PiP，並在設定變更時即時更新。
4. `pitch-labels.ts` 分別附加原文與發音標籤。
5. `pip.ts` 用同一批已評分麥克風樣本渲染所選模式。

模式切換只改繪圖策略，不重建 `ScoreTracker`、不清空樣本，也不重設分數。

## 錯誤與邊界處理

- 麥克風未啟動：不推進分數，不繪製命中覆蓋。
- 麥克風已啟動但無聲：時間照常推進，未唱音符維持暗色。
- 樣本不在可見時間窗：可以送入評分器，但不繪製。
- 樣本落在兩顆相接音符邊界：優先選擇從該時間開始的下一顆音符。
- 音符沒有對應原文字：保留音符條，不畫空標籤。
- 發音位置在底部：只移動 `pron`，不影響 `lyric`。

## 測試

先建立失敗測試，涵蓋：

1. 原文標籤與發音標籤分離。
2. 沒有發音資料時，音符原文仍存在。
3. 發音位置為底部時，原文仍由音符繪製路徑使用。
4. `line`、`dots` 舊設定正規化為 `trace`。
5. 設定型別只接受 `trace | notes`，預設為 `notes`。
6. 設定頁含兩個採點顯示選項。
7. PiP 快速按鈕在 `trace` 與 `notes` 間切換並保存。
8. 命中音符模式使用評分結果繪製金／黃／紅覆蓋層。
9. 線條模式仍使用分段軌跡，切換不重設分數。

完成後執行 Chrome 擴充功能全量測試、採點自檢腳本、正式建置與 diff 格式檢查。
